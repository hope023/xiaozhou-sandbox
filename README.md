# 小舟沙盒本地加密保险库。文件内容、文件名、目录结构、设置全部加密存放在你自己的磁盘上。
没有服务器，没有账号，不联网。**纯 Rust + egui 单文件程序，无 WebView、无运行时依赖。**> **它是什么**：一个把文件加密后再存进自己磁盘的桌面工具，打开时即时解密，退出后磁盘上只有密文。

数据是你自己的，拿出去不该需要付费。## 加密设计```
主密码 ──Argon2id(salt, m=64MiB, t=3, p=4)──► KEK
                                                │
                            ┌───────────────────┴───────────────┐
                            ▼                                   │
                    解开 keyslot（XChaCha20-Poly1305）            │
                            │                                   │
                            ▼                                   │
                          DEK（32 字节数据密钥）◄────────────────┘
                            │
              ┌─────────────┴─────────────┐
              ▼                           ▼
      HKDF("xvault-blob-v1")      HKDF("xvault-index-v1")
              │                           │
              ▼                           ▼
      每文件 1 MiB 分块加密        索引整体加密（含文件名与目录树）
```

- 换密码只重新封装 DEK，不重新加密所有文件，所以是秒级的。
- 每个密文块都用 AAD 绑定所属文件，把 A 文件的密文挪到 B 文件的位置上会解密失败，
  而不是静默显示 A 的内容。
- 磁盘上**没有**文件名、目录名、MIME、大小之外的明文元数据。剩下的泄漏只有密文体积本身。

## 隐私输入

打开文本文件后，点底部的「隐私输入」，中文就不再经过系统输入法。

**为什么需要它**：系统输入法会把你的打字记进用户词库（如 `ChsPinyinHR.udp`）、云候选和账号学习历史。
换哪个输入法都一样，这是 IME 的工作机制决定的，不是某家厂商的问题。

**怎么做到**：

1. 输入区不是任何可编辑控件（TextEdit 会激活 TSF），而是一个自绘组件直接消费原始键盘事件、
   自己拼字。焦点不落在可编辑控件上，Windows 的 TSF 就不会激活输入法——这是主防线。
2. 同时把主窗口及其子窗口的 IME 上下文解绑（`ImmAssociateContextEx`），离开时恢复。
   这是双保险，因为有些输入法跟随窗口而不是跟随控件。

**词库**：约 2.1 万个汉字 + 6 万个词组，来自 `pinyin-data`、`phrase-pinyin-data`、`jieba`（均 MIT 许可），
构建期生成为两个 JSON，随应用离线打包。打字过程不联网、不上传、不写系统词库。

**限制**（不打算掩饰）：

- 只能在末尾追加和退格，不支持中间插字、选区、撤销栈
- 不支持简拼、手写、语音输入
- **防不住键盘钩子、屏幕录制、内存取证**——那是操作系统层的事，输入法无能为力

## 支持的格式

| 类型 | 说明 |
|---|---|
| 文本 | UTF-8 / GBK 容错的纯文本、Markdown、代码、CSV、日志等，超过 4 MB 只读（禁止覆盖保存） |
| 图片 | PNG / JPEG / GIF / WebP / BMP，上限 24 MB（egui 版暂不支持 SVG）；GIF 按帧延时播放动图 |
| 视频 | 内嵌播放：播放/暂停、拖动进度、有声音；快捷键 空格=播放/暂停，←/→=后退/前进 10 秒。用 Windows 自带的 Media Foundation 解码，明文由保险库按需解出（4 MB 滚动窗口），不写临时文件；文件多大都能播，内存占用与文件大小无关 |
| 音频 | 暂不内嵌播放。提供「解密导出到本地…」，导出后用系统播放器打开 |
| 其他 | 不内联预览，可直接导出 |

> 视频解码器是系统组件（mfreadwrite.dll / winmm.dll），没有引 FFmpeg，也没有 GPL 牵连。
> 4K 源会在解码时降采样到 1280 宽再上纹理。系统缺对应解码器（如未装 HEVC 扩展）时
> 会明确提示，并保留「解密导出」这条退路。

## 系统要求

- Windows 10 1809 及以上（反截屏需要 2004+）
- 单个 exe 约 11 MB，无安装、无运行时依赖（不需要 WebView2）
- 数据目录：`%APPDATA%\com.xiaozhou.sandbox`；默认库位置：`%LOCALAPPDATA%\com.xiaozhou.sandbox\vault`（与原 Tauri 版相同，旧库直接可解锁）

## 从源码构建

```bash
cargo run              # 开发
cargo test             # 测试（核心加密库 + 隐私输入引擎）
cargo build --release  # 产物：target/release/xiaozhou-sandbox.exe（单文件，约 11 MB）
```

技术栈：`eframe/egui`（即时模式 GUI）+ 原核心加密库（Argon2id / XChaCha20-Poly1305）。
前端不再有 Node/npm/Vite；输入法词库以 `include_str!` 嵌入 exe。

## 打安装包

需要 [NSIS](https://nsis.sourceforge.io/) 3.x（`makensis` 在 PATH 里即可）：

```bash
cargo build --release
makensis installer/setup.nsi   # 产物：dist/小舟沙盒-0.1.0-安装包.exe
```

安装到 `%PROGRAMFILES64%\XiaozhouSandbox`（目录名用 ASCII，快捷方式和显示名仍是中文），创建桌面与开始菜单快捷方式，注册卸载项。
**卸载只删程序，不删保险库和配置**——数据留给你自己决定。
静默安装/卸载用 `/S`。

## 费用

**当前版本全部功能免费，界面上没有授权入口，也没有任何付费墙。**

代码里还留着一套离线签名授权的设施（`src/license.rs`，`GATING_ENABLED = false`），
默认关闭、不参与任何决策。将来若真要做收费版本，把它改成 `true` 就能恢复门控，
不需要改其它代码。保留它的理由是：门控点散落在 8 个命令里，删掉容易，将来补回来容易漏。

授权是离线校验的 Ed25519 签名文件，公钥硬编码在二进制里，私钥不进仓库。

```bash
node private-tools/sign.mjs --email user@example.com --plan pro --days 365
```

`private-tools/license-key.json`（私钥）在 `.gitignore` 里。私钥丢失只影响你签发新授权，
泄漏则意味着任何人都能伪造授权——请像对待代码签名证书一样对待它。

`private-tools/sign.mjs` 只是签发工具，不含密钥，**要入库**，否则换机器就断在这里。
